# Notion 연결 규칙 v0.2.1

이 문서는 개인 실행관리 AI가 사용자의 Notion `윤지의 실행 관리 · 통합 대시보드`를 장기 상태 저장소로 사용할 때 적용한다. Goal, Project, Task, Routine, Daily Log, Idea, Feedback, Fixed Event, Time Log를 하나의 `통합 실행 DB`에 저장하고 화면별로 필터링한다. 데이터베이스를 다시 만들지 말고 이 구조를 사용한다.

## 연결 프로필

- 워크스페이스 이름: `윤지 정의 Notion`
- 대시보드 페이지: `윤지의 실행 관리 · 통합 대시보드`
- 대시보드 페이지 ID: `3db4b49f-4c7b-8180-a5d1-e3399d212329`
- 통합 실행 DB: `https://app.notion.com/p/f7f27253e7334826baabe25526673a87`
- 통합 실행 데이터 소스: `collection://c6e6ccd5-06b7-491f-bc0d-a0c7414c8aa0`
- 기본 시간대: `Asia/Seoul`

ID는 2026-09-14에 생성 후 읽어 확인한 값이다. ID 조회가 실패하면 Notion에서 정확한 제목 `윤지의 실행 관리 · 통합 대시보드`를 검색하고, 찾은 페이지를 fetch하여 `통합 실행 DB`의 데이터 소스 URL을 다시 확인한다. 같은 제목이 여러 개면 임의로 쓰지 말고 사용자에게 대상을 구분해 달라고 요청한다.

## 연결과 조회 순서

1. 현재 세션에 Notion 도구가 없으면 `disconnected`로 처리한다. 도구가 있으면 `fetch("self")`로 워크스페이스와 현재 도구 접근 상태를 확인한다.
2. 대시보드 또는 통합 실행 데이터 소스를 fetch하여 스키마가 아래 필드와 호환되는지 확인한다. 한 번 확인한 스키마는 같은 요청 안에서 다시 읽지 않아도 된다.
3. 전체 워크스페이스를 훑지 않는다. 요청과 관련된 활성 목표·프로젝트, 미완료 Task, 해당 기간 Routine, 일정·실제 마감, 최근 7일 실행 기록만 query한다. 정확한 대상 ID가 있으면 그 페이지만 fetch한다.
4. 빈 조회 결과와 조회 실패를 구분한다. 오류나 불완전한 범위에서는 “기존 항목 없음”이나 전체 진척률을 단정하지 않는다.

읽기 전용 요청은 여기서 멈추고 답한다. 쓰기 요청은 아래 매핑과 저장 규칙을 따른다.

## 통합 실행 DB 필드 매핑

모든 유형과 실행 기록은 `통합 실행 DB` 한 곳에 저장한다. `유형`으로 레코드의 역할을 구분한다.

| 논리 필드 | Notion 속성 | 사용 규칙 |
|---|---|---|
| title | 이름 | 항상 입력하는 제목 |
| type | 유형 | Goal / Project / Task / Routine / Daily Log / Idea / Feedback / Fixed Event / Time Log |
| status | 상태 | 수집함 / 계획됨 / 진행 중 / 막힘 / 완료 / 취소 |
| source_note | 원래 표현 | 사용자의 원래 말을 필요한 범위로 짧게 보존 |
| goal_id | 상위 Goal | Goal 페이지 URL 또는 ID의 relation 배열 |
| project_id | 상위 Project | Project 페이지 URL 또는 ID의 relation 배열 |
| why | 메모 | Goal의 목적과 배경 |
| success_criteria | 성공 기준 | Goal·Project·Routine의 성공 기준 |
| done_when | 완료 기준 | Task의 완료 기준 |
| due_date | 실제 마감 | 사용자가 정하거나 외부 약속으로 정해진 날짜 |
| target_date | 일정 | AI가 제안하거나 사용자가 배치한 실행 날짜. 시간 기록은 시작·종료 범위를 사용 |
| estimate_minutes | 예상 시간(분) | 숫자 |
| remaining_minutes | 남은 시간(분) | 숫자 |
| effort | 노력도 | high / medium / low. 중요도와 별개 |
| importance | 중요도 | 높음 / 중간 / 낮음 |
| progress | 부분 진행 % | 0~100. 완료 체크 시 직접 실행률은 100으로 계산 |
| completed | 완료 | Task·Time Log 등 실행 단위의 완료 체크 |
| progress_targets | 진척 대상 | Goal·Project의 계획 실행률에 포함할 말단 Task 관계 |
| frequency | 반복 주기 | 사람이 이해할 수 있는 반복 규칙 |
| cue | 시작 계기 | Routine을 시작하는 조건 |
| fact | 사실 | 실행 결과나 회고의 관찰 사실 |
| feeling | 느낀 점 | 사용자의 소감 |
| next_adjustment | 다음 조정 | 다음 계획에 반영할 조정안 |
| related_items | 관련 항목 | Feedback·Time Log 등이 연결되는 항목 |
| linked_routine | 연결 Routine | 날짜별 기록이 가리키는 Routine 정의 |
| depends_on | 선행 작업 | 먼저 끝나야 하는 Task 관계 |
| completed_at | 완료일 | 완료를 보고한 날짜 또는 시각 |
| start_date | 시작일 | Routine 시작일 |
| standard_minutes | 기본 분량(분) | Routine의 기본 실행 분량 |
| minimum_minutes | 최소 분량(분) | 힘든 날에도 유지할 최소 분량 |

날짜는 Notion 쓰기 형식인 `date:속성명:start`와 `date:속성명:is_datetime`으로 보낸다. 관계는 연결된 페이지 URL 또는 ID 배열로 보낸다. 알 수 없는 선택 속성 값을 새로 만들지 말고 비워 두거나 사용자 표현을 원래 표현·본문에 보존한다.

상태는 다음 뜻으로 일관되게 사용한다.

- `수집함`: 아직 실행 약속을 하지 않은 Idea 또는 정리가 필요한 항목
- `계획됨`: 실행하기로 정했고 아직 시작하지 않은 Goal·Project·Task·Routine
- `진행 중`: 현재 실행 중인 Goal·Project·Task·Routine
- `막힘`: 외부 조건이나 선행 작업 때문에 진행할 수 없음
- `완료`: Goal 달성, Project·Task 완료, Idea 전환 완료
- `취소`: 취소·종료·보관한 항목

Idea에는 실제 마감과 일정을 강제로 넣지 않는다. 완료한 Task에는 `완료=true`, `상태=완료`를 함께 저장한다. 완료 정정으로 다시 열면 두 속성을 함께 갱신하고 관련 Feedback에 정정 사실을 남긴다.

## 날짜별 Routine과 실행 기록

| 레코드 | 유형 | 주요 Notion 속성 |
|---|---|---|
| 날짜 기록 | Daily Log | 이름, 일정, 오늘 할 일, 여섯 Routine 체크박스, 사실, 느낀 점, 다음 조정 |
| 계획·고정 일정 | Fixed Event | 이름, 일정 시작·종료, 중요도, 관련 항목 |
| 실제 시간 기록 | Time Log | 이름, 일정 시작·종료, 실제 시간(분), 상위 Project, 관련 항목 |
| 실행 회고 | Feedback | 이름, 일정, 관련 항목, 사실, 느낀 점, 다음 조정 |

계획일만 필요한 간단한 Task는 `일정`에 날짜만 저장한다. 실제 시작·종료 시각을 기록할 때는 Time Log를 추가하고 원래 Task를 `관련 항목`으로 연결한다. 같은 Task를 여러 시간대로 나눠도 Task 자체를 복제하지 않는다.

대시보드의 연결 보기에서는 원본 이름 `통합 실행 DB`를 숨기고, 맨 아래 `전체 DB`에서만 표시한다. `주간 일정`과 `주간 Time Log`는 모두 7일 보기로 유지한다. Notion 페이지 안의 주간 캘린더는 날짜 열만 제공하므로, 세로 시간축 블록은 연결된 Notion Calendar에서 확인한다. `일정`에 시작·종료 시간을 입력한 Time Log 또는 Fixed Event는 같은 레코드가 시간 길이만큼 블록으로 표시된다. Daily Log의 `시간 관리` 체크박스는 루틴 실행 여부이며 시간 블록을 만들지 않는다.

Routine 정의는 한 번만 만들고 날짜별 결과는 하루 한 개의 Daily Log에 저장한다. Daily Log에는 `일기 작성`, `운동`, `시간 관리`, `성경 읽기`, `뉴스 스크랩`, `가계부 작성` 체크박스가 있다. 여섯 항목은 모두 매일 도래하며 `Daily 골밀도`는 체크 수 ÷ 6으로 자동 계산된다. 중복 방지를 위해 같은 날짜의 Daily Log가 있는지 먼저 확인한다.

Daily Log의 `오늘 할 일`에는 그날의 Task·Routine·Fixed Event·Time Log를 연결한다. `오늘 전체 실행률 %`는 연결 항목의 직접 실행률과 여섯 Routine 체크를 같은 실행 단위로 합산한다. Goal·Project의 `계획 실행률 %`는 `진척 대상`에 연결된 말단 Task의 직접 실행률 평균이며 실제 결과 지표의 달성률로 표현하지 않는다.

## 생성·수정·검증

- 생성 전 같은 유형·제목·부모 관계·기간의 항목을 조회한다. 유사 제목만으로 자동 병합하지 않는다. 확실한 중복은 update하고, 구분이 필요한 경우에만 짧게 질문한다.
- 신규 항목과 실행 기록은 모두 페이지 생성 도구에서 `통합 실행 데이터 소스` ID를 parent로 사용한다. 제목 속성 `이름`과 `유형`, 필요한 경우 `상태`를 포함하고 알려진 필드만 추가한다.
- 기존 항목 변경은 먼저 페이지를 fetch한 후 속성 update를 사용한다. 생략한 속성은 유지한다. 페이지 본문을 변경하지 않아도 되는 작업은 속성만 수정한다.
- 같은 도구 응답이 불명확하거나 시간 초과가 나면 생성 요청을 바로 반복하지 않는다. 제목·유형·관계·날짜로 재조회하여 저장 여부를 확인한 뒤 필요한 변경만 수행한다.
- 생성 결과의 페이지 URL·ID를 후속 관계와 기록에 사용한다. 여러 항목 생성 중 일부만 성공하면 성공한 URL을 보존하고 실패한 항목만 미저장 변경안으로 남긴다.
- 쓰기 후 신규 페이지 또는 수정한 페이지를 fetch하거나 관련 범위를 query하여 핵심 속성을 확인한다. 확인된 경우에만 `저장 완료`라고 말한다.

## 요청별 기본 처리

| 사용자 표현 | 처리 |
|---|---|
| “현재 목표 보여줘” | 활성 Goal·Project를 조회하고 저장하지 않음 |
| “오늘 할 일 정해줘” | 미완료 항목과 오늘 가용 시간을 바탕으로 제안만 작성 |
| “오늘 계획을 저장해줘” | 채택된 Task 일정 또는 Fixed Event를 저장하고 Daily Log에 연결한 뒤 검증 |
| “이것도 해야 해. 저장해줘” | 분류·필요한 최소 질문 후 통합 실행 DB에 생성 |
| “30분 했지만 못 끝냈어” | 대상 Task를 진행 중으로 유지하고 부분 진행·실제 시간을 갱신하며 Feedback 또는 Time Log 추가 |
| “영어 공부 끝냈어” | 문맥상 대상이 하나면 완료 또는 Daily Log의 Routine 체크를 기록하고, 여러 후보면 대상만 확인 |
| “다음 주로 미뤄줘” | 실제 마감은 유지하고 일정만 변경 |
| “이번 목표 취소할래” | 영향받는 활성 작업을 보여준 뒤 선택한 범위의 상태를 취소로 변경 |

## 연결 실패 시

인증 만료, 권한 부족, 도구 부재, 대상 페이지 삭제·이동으로 연결하지 못하면 오류를 짧게 설명한다. 가능한 계획 작업은 계속하고 저장 인터페이스의 ChangeSet으로 `미저장 변경안`을 제공한다. 성공 여부가 불확실한 쓰기는 중복 생성하지 말고 다음 연결 시 먼저 조회한다.
